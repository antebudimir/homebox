# Code Quality

## Backend (Go)

- Idiomatic Go: return errors, wrap with context, no panics in request paths.
- Keep handlers thin: validate → authorize → service → repo (`errchain` handlers in `backend/app/api/handlers/v1/`).
- Business logic lives in `backend/internal/core/services/`; DB access lives in `backend/internal/data/repo/`. Do not query ent from handlers.
- Pass the request context down; never `context.Background()` inside a request path.
- ent for all queries; raw SQL only inside goose migrations.
- Table-driven tests with `testify`; name tests for behaviour, not implementation.

## Frontend (Vue, TypeScript)

- `<script setup lang="ts">`; avoid `any` in new code — prefer the generated contract types.
- API types come from `frontend/lib/api/types/data-contracts.ts` (generated by `task typescript-types`) — regenerate, never hand-edit.
- Shared state goes in a composable (`frontend/composables/use-*.ts`) or a Pinia store (`frontend/stores/`), not in page-local refs when reused.
- `frontend/components/ui/**` is vendored ShadCN — style around it, do not rewrite it.
- Every user-visible string goes through i18n (`$t`), keys in `frontend/locales/*.json`.

## Tests

- Add tests with the change: Go `*_test.go` next to the code; frontend Vitest in `frontend/lib/api/__test__/`; Playwright in `frontend/test/e2e/`.
- Derive expected values; never hardcode today's date, locale or timezone.

## Hygiene

- No dead code, no commented-out blocks, no TODO without a tracked reason.
- Name things after the domain (`build`, `build part`, `usage session`, `sport`), not after upstream's old names (`setup`).

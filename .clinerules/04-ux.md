# UX

## Theming

- Theme state lives in `frontend/composables/use-preferences.ts` (`theme`, `themeLight`, `themeDark`); valid names are the daisyUI themes in `frontend/lib/data/themes.ts`.
- The toggle is `frontend/components/App/ThemeToggle.vue`, mounted in the header (`frontend/layouts/default.vue`). Keep it in the header.
- Never hardcode colours; use the theme tokens and utility classes neighbouring components already use.
- Verify light and dark on every screen you touch.

## States

- Every async view needs loading, empty and error states — not just the happy path.
- Empty states say what to do next, in localized copy.
- Surface failures as toasts; warnings that matter must stay visible long enough to read (the toast stack is sized for multiple messages — do not collapse it).
- Keep layout stable while loading: no jumping headers, no zero-height placeholders.

## Interaction

- Destructive actions confirm first (delete group, remove member, delete build).
- Icon-only buttons get a tooltip and an accessible label.
- Check mobile and desktop widths: no overflow, no clipped labels.

## Copy

- All strings through i18n; sentence case, imperative.
- Builds vocabulary: "build" (not "setup"), "part", "position", "sport".
